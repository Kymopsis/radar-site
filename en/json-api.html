JSON results and API

Every client - the app, Home Assistant, your own code - reads the same results: one JSON object per line, schema version 0.

Where to read them

ConnectionHow
USBSend jsonout on on the serial console; JSON lines arrive between log lines
Wi-FiWebSocket ws://kymradar.local/ws (one or more lines per message)

Messages

tFieldsNotes
capapp (hd3d, fall, vital), mounts, mountSent when a scenario starts, when the mounting changes, and every 5 s
targetsts (ms), targets: [{id, x, y, z}]Metres. x right, y away from the radar (floor plane when on the ceiling), z up
zoneszones: [{id, occupied}]Areas 1-4; sent on change and every second
fallstate (none, normal, fall), countSent on change and every second
vitalts, br, hr (per minute), dist (m)Rates omitted while nobody is measured

Every message has "v": 0. Ignore messages with another version.

{"v":0,"t":"cap","app":"hd3d","mounts":["ceiling","side"],"mount":"side","fov_deg":55}
{"v":0,"t":"targets","ts":42097,"targets":[{"id":1,"x":0.268,"y":1.42,"z":0.05}]}

Commands (USB console or app)

CommandWhat it does
verAsk the radar app for its version
ram <file>Run a radar app from the radar's memory
resetRestart the radar from its flash
jsonout on/offJSON results on USB
tf 0201 13000000 / 140000003D presence: ceiling / wall mounting
cfg [key value]Raw-data settings
wifi [ssid password], wifi forget, wifi scanHome Wi-Fi
api files/cfg/wifi/scan/mqtt/batchDevice info as one JSON line (used by the app over USB)
mqtt <host> [port] [user] [pass], mqtt offHome Assistant over your own MQTT broker
board [profile]Show or set the board profile
u0raw on/offForward the radar app port byte for byte (raw capture)
batch start <firmware>, batch stopBatch flashing (dev-kit firmware)

HTTP API (Wi-Fi)

GET /api/files, GET/POST /api/cfg, GET/POST /api/wifi, GET /api/wifi/scan, POST /api/run?op=..., POST /api/tf?type=&data=, GET /api/log?since=. Credentials are only ever sent in a POST body.
