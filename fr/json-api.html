Résultats JSON et API

Tous les clients - l'appli, Home Assistant, votre propre code - lisent les mêmes résultats : un objet JSON par ligne, schéma version 0.

Où les lire

ConnexionComment
USBEnvoyez jsonout on sur la console série ; les lignes JSON arrivent entre les lignes de journal
Wi-FiWebSocket ws://kymradar.local/ws (une ou plusieurs lignes par message)

Messages

tChampsRemarques
capapp (hd3d, fall, vital), mounts, mountEnvoyé au démarrage d'un scénario, quand le montage change, et toutes les 5 s
targetsts (ms), targets: [{id, x, y, z}]Mètres. x à droite, y en s'éloignant du radar (plan du sol quand il est au plafond), z vers le haut
zoneszones: [{id, occupied}]Zones 1-4 ; envoyé à chaque changement et toutes les secondes
fallstate (none, normal, fall), countEnvoyé à chaque changement et toutes les secondes
vitalts, br, hr (par minute), dist (m)Fréquences omises tant que personne n'est mesuré

Chaque message contient "v": 0. Ignorez les messages d'une autre version.

{"v":0,"t":"cap","app":"hd3d","mounts":["ceiling","side"],"mount":"side","fov_deg":55}
{"v":0,"t":"targets","ts":42097,"targets":[{"id":1,"x":0.268,"y":1.42,"z":0.05}]}

API HTTP (Wi-Fi)

GET /api/files, GET/POST /api/cfg, GET/POST /api/wifi, GET /api/wifi/scan, POST /api/run?op=..., POST /api/tf?type=&data=, GET /api/log?since=. Les identifiants ne sont jamais envoyés que dans le corps d'un POST.

Exemple de client en Python : python app_views.py --serial COM5 dans le dossier pc-gui.

Volumes, modules préflashés ou firmware sur mesure : Kymopsis B2B
